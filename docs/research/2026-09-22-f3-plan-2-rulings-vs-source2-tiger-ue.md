## Sources actually read

- VRF release 19.1 notes (verbatim): "Scene rendering now uses a GPU-driven culling pipeline. A compute shader tests every meshlet AABB against the camera frustum, a hierarchical depth pyramid (occlusion culling), and a screen-size threshold." and "Meshlet level culling is available on most Source 2 maps built 2023 and forward."

## Plan contracts checked against the targets while at it

- Transparent order. VRF: per DRAW CALL by Euclidean camera distance, far to near, unstable sort, no render-order integer for translucents (overlays have one). Tiger: per-stage sort keys, back to front, per draw call if the feature wants (GDC 2015 p183-184); Destiny 1 bucketed low-res transparents by depth. UE: priority-major key (a depth-independent render order, larger draws later), default metric = distance to the bounds origin, projected Z optional, per-primitive distance offset, no identity tie-break. Ours = render order asc, projected view-Z desc, stable (entity, mesh, section) identity, plus a sort offset. Verdict: ours is a superset of all three (explicit order AND deterministic ties). The one divergence: both Source 2 and UE's DEFAULT sort by Euclidean distance to the bounds origin; we sort by projected view-space Z (spec s7; UE offers it as policy 1). Deliberate, not a defect; note for the MBOIT/refraction seam owner.
- Alpha test draws AFTER opaque and primes depth: VRF orders opaque 0 -> alpha-test 1 -> overlay 2 within the opaque pass (MeshBatchRenderer.cs:69-73) and routes alpha-test draws into the depth prepass; UE renders masked in the base pass with depth write (or `CF_Equal` after early-Z). Ours emits opaque -> masked. Matches.
- Translucent depth state: VRF `depthWrite: false, blend: true` with the test on (Scene.cs:2115); UE `<false, CF_DepthNearOrEqual>`. Ours: transparent tests, never writes; masked and opaque write. Matches. (Our `translucencyDepthSortBias` is a SORT offset like UE's `TranslucencySortDistanceOffset`, not Source 2's rasterizer `F_DEPTHBIAS`.)
- Alpha cutoff default 0.5: matches `g_flAlphaTestReference` (RenderMaterial.cs:571-572).
- Offline shader variants, no runtime define mechanism: TFX builds variants offline from variant layers and `@compile_if` labels (p254-266); Source 2 ships compiled `.vcs` per static feature combo selected by the `F_*` params; UE compiles `MATERIAL_TWOSIDED` etc. as offline permutations. Matches the plan's non-negotiable.
- Two-sided lighting: UE flips the normal for back faces (`TwoSidedSign`, Q7). Ours does not (already an owed item); the reference confirms it is expected behaviour for a two-sided material.
- GPU-driven culling is the target's own direction: Valve's compiled meshes carry per-meshlet cone + AABB cull data (`m_CullingData`, Meshlet.cs:77-91) on maps built since 2023 (release 19.1). Our F3 cull is per row (per mesh-section instance), frustum only; meshlet granularity, cone/backface culling and Hi-Z occlusion are the natural next steps on the same pipeline shape.

## What this changes

Nothing on the branch. Four already-owed items gain reference backing and should be scheduled in this order:
1. I1 host-gate residual: publish an empty result for a frame that declares no mesh pass (UE never shows an older frame's count).
2. Args-only arming mode for the hosts' HUD (all three references keep stat readbacks tiny or GPU-side).
3. Golden gate: editor lanes compare the viewport (or a chrome-masked frame), not the whole editor window (UE excludes UI structurally; no masks exist there either, so it excludes rather than masks).
4. Two-sided lighting flips the normal for back faces (UE `TwoSidedSign`).

Two deliberate divergences to keep on record: cull polarity (we zero-then-increment like UE; VRF ones-then-zeroes) and the translucent depth metric (we use projected view-Z; Source 2 and UE's default use Euclidean distance to the bounds origin).
