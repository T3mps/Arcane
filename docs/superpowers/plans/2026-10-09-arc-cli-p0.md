# arc CLI P0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A loopback `arc` CLI can attach to a running Arcane editor, headless runtime, or dedicated server, call the P0 command set (including play/step), and get one JSON envelope back.

**Architecture:** `ArcaneCore` owns the protocol, the command registry, a 127.0.0.1 HTTP listener, the descriptor, and the main-thread dispatcher. Each host arms that listener and drains the queue once per tick before it simulates. `arc.exe` is a thin console app over `Arcane::Arc::Cli` in Core; it never links `ArcaneClient`. Astra's JSON Schema generator learns `Optional` and real defaults upstream, then this repo vendors the headers. The settings-era `RemoteCVarService` and the editor's `DiagnosticStore` move into shapes every host can call.

**Tech Stack:** C++23, premake5, MSBuild (VS 2026), Catch2 v3, rapidcheck, nlohmann::json, Astra ECS, Win32 DACL, PowerShell.

**Spec:** `docs/superpowers/specs/2026-10-05-arc-cli-design.md`. Section 0 decisions 0.1–0.28 are accepted as recommended. Section 0.29 amendments AM1–AM6 are binding. This plan is s13 P0 plus the "P0 additions (2026-10-09)" paragraph (play|stop|pause|resume|step, AM1–AM6, `ecs.archetypes`). It does not build P1–P4. Research `docs/research/2026-10-05-arc-cli-research.md` is background; where it and the spec disagree, the spec wins. Where this plan and the spec disagree on a line number or a type that has moved, the **Tree facts** below win — they were read off this worktree (`feat/arc-cli`, `576f01ee`), which already contains the settings arc (ABI 54).

## Review Focus

These five are the inputs most likely to bite a user that a happy-path test would miss. Each one has a pinning test in the task named, written in that task's own step.

1. **The listener forgets the bind address and calls `CreateListenSocket(port)`.** The default is `INADDR_ANY` (`TcpSocket.hpp:203-206`), so the port is reachable off-machine. A reasonable person expects the socket's bound address to be `127.0.0.1` and nowhere else. Pinned in Task 9 (`"the listen socket is bound to 127.0.0.1"`).
2. **A request carries the right bearer token and also an `Origin` header, or a `Host` that is not `127.0.0.1:<port>` or `localhost:<port>`.** DNS rebinding. A reasonable person expects refusal before the command runs. Pinned in Task 9 (`"a good token does not survive Origin or a foreign Host"`).
3. **The editor is minimized.** A queued `cvar.get` must still run, a screenshot must return `host.busy` with `state:"minimized"` and exit 5 without grabbing pixels, and the client must return rather than hang. Pinned in Task 16 (`"minimized: cvar.get runs, screenshot does not, and the waiter returns"`).
4. **The token is written to a log line, an envelope, a descriptor dump, or `arc --verbose`.** A reasonable person expects the secret absent from all four. Pinned in Task 18 (`"verbose and human output redact the bearer token"`), with the listener-side half in Task 9 (`"a refused request does not log the token"`).
5. **`play.step 10` on an `--arc` headless runtime that was not given `--frames`, or the same step on ArcaneServer.** A reasonable person expects `host.frame` to advance by exactly 10 and then stop, counting sim ticks rather than rendered frames. Pinned in Task 30 (`"headless runtime step 10 advances host.frame by exactly 10 and then stops"` and `"ArcaneServer step 10 counts ticks, not rendered frames"`).

These are also pinned, in the task that owns them, and are not repeated as a sixth header line: a recycled pid (Task 10), a Protected cvar read from the Editor context (Task 23), `--all` worst-exit when one host is busy (5) and another is dead (7) (Task 22), and a compare that ran and failed (`ok:true`, exit 8) (Task 29).

#ifdef _WIN32
    if (info.pid == 0) return false;
    HANDLE h = ::OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION, FALSE, info.pid);
    if (!h) return false;
    FILETIME created{}, exited{}, kernel{}, user{};
    const bool ok = ::GetProcessTimes(h, &created, &exited, &kernel, &user);

    if (!ok) return false;

    if (info.start != 0 && info.start != start) return false;

    return true;
#else

    return false;

}

class TickGate {
public:
    void SetRunning(bool running);     // play / stop
    void SetPaused(bool paused);       // pause / resume; resume is SetPaused(false) while running
    void RequestSteps(std::uint32_t n);

    bool Running() const;
    bool Paused() const;

`Consume` truth table:

| running | paused | steps | result |
|---|---|---|---|
| false | * | 0 | Idle |
| false | * | >0 | Step, then decrement (a step while stopped still runs N ticks — `play.step` on a stopped host is how Task 30 defines "advance exactly N") |
| true | false | * | Run (steps are not consumed; free-run ignores a leftover count by clearing it) |
| true | true | 0 | Idle |
| true | true | >0 | Step, then decrement |
